# AuditLab — RL-среда финансового аудита

Рабочее автономное решение FinTech-кейса GENESIS 2026. Генератор создаёт синтетическую компанию, документы и скрытые ошибки; агент расследует их через ограниченные инструменты. Оценщик сопоставляет выводы с причинным эталоном и рассчитывает награду. Обучение весов не выполняется.

## Веб-интерфейс

На Windows дважды нажмите `start-ui.cmd` в папке проекта. Или выполните:

```sh
python -m auditlab.web --open
```

Откроется http://127.0.0.1:8765. Сервер должен оставаться запущенным; остановка — Ctrl+C в терминале. Если порт занят, используйте `python -m auditlab.web --port 8766 --open`.

В интерфейсе выберите seed, размер и сценарий → «Создать компанию» → «Запустить аудит». Доступны проводки, счета, платежи, FX и политика, F1/награда, выводы с ID доказательств, журнал и скачивание траектории. Можно читать документы, пользоваться калькулятором и отправлять собственный массив findings. Чтение и калькулятор во время эпизода расходуют шаги; просмотр уже полученных страниц после завершения бесплатный. Непрочитанные страницы после завершения не открываются.

После завершения доступна кнопка «Сравнить на этой компании»: сверка, случайный исследователь и атака «пометить всё» запускаются с одним seed/config и отдельными полными бюджетами. Текущий аудит не меняется. Таблица показывает F1, награду, TP/FP/FN, шаги и время; «Скачать прогоны» выгружает реальные JSONL-траектории всех трёх политик. Oracle остаётся в доверенной CLI-проверке.

Каждый вывод получает отметку «Подтверждено оценщиком» или «Не сопоставлено с эталоном» по результату взаимно однозначного matcher, а не по тексту объяснения. Нажатие ID доказательства открывает только запись, уже полученную в наблюдениях; скрытый эталон и непрочитанные записи не подгружаются. Таймер показывает оставшееся время эпизода; фактическое усечение по времени проверяет ядро при следующем действии. При обновлении кода перезапустите сервер (Ctrl+C, затем команда запуска), чтобы загрузить новую серверную логику.

Это открытый train-режим поверх настоящего ядра, с тем же бюджетом 100 шагов и лимитом 60 секунд с момента создания компании. Для длительного изучения сначала выполните аудит и изучайте полученные записи после завершения. Действует одна общая сессия на сервер: вкладки браузера показывают один и тот же эпизод. Перезапуск очищает сессию; для сохранения действий используйте «Скачать траекторию». Закрытая проверка по-прежнему запускается через доверенный runner, не через демонстрационную страницу.

Интерфейс полностью локальный, без CDN, внешних шрифтов, сторонних библиотек и API. Слушает только loopback; изменение данных требует непредсказуемого токена, проверяется Host. Это не публичный многопользовательский хостинг. Не передавайте доступ к локальному серверу недоверенным пользователям.

## Запуск одной командой

Требуется Python 3.11 или новее, сторонних зависимостей нет. Из корня проекта:

```sh
python -m auditlab.verify
```

Команда запускает тесты, независимую проверку согласованности, четыре политики на одинаковых 20 эпизодах, 20 парных проверок переименования/перестановки для всех четырёх политик (80 сравнений) и экспортирует материалы в `artifacts/`. В наборе 5 чистых и 5 взаимодействующих эпизодов. Ошибка проверки завершает программу ненулевым кодом. Эпизоды и изменения воспроизводимы; измеренное время зависит от машины.

Быстрое интерактивное по шагам демо в терминале:

```sh
python -m auditlab.demo --seed 2026 --policy reconcile --interaction fx_cutoff
python -m unittest discover -s tests -v
```

`demo-trajectory.jsonl` содержит действия, наблюдения и награды открытого train-режима. `artifacts/trajectories.jsonl` содержит траектории evaluation-режима с нулевой передаваемой наградой. Итоговые метрики доступны только доверенному runner, в `artifacts/evaluator-reports.json` и `metrics.json`.

## Контейнер

Сначала собрать образ (эта стадия скачивает официальный базовый Python-образ), затем проверять без сети:

```sh
docker build -t auditlab .
docker run --rm --network none --cpus 2 --memory 4g --pids-limit 64 auditlab
```

В контейнере нет сторонних pip-зависимостей, модельных API, GPU или сетевых обращений. Чтобы сохранить результат на Linux/macOS, добавьте `-v "$PWD/results:/app/artifacts"`; каталог должен быть доступен для записи пользователю runner. На Windows проще воспользоваться локальной Python-командой. Dockerfile подготовлен; локальная проверка здесь выполнена на Windows с Python 3.12, Docker в среде сборки отсутствовал.

## Контракт среды

```python
from auditlab import AuditEnv

with AuditEnv() as env:
    observation, info = env.reset(seed=42, config={"interaction": "fx_cutoff"})
    observation, reward, terminated, truncated, info = env.step({
        "action": "list_records", "table": "ledger", "cursor": 0, "limit": 50
    })
```

Действия: `list_records(table,cursor=0,limit=50)`, `get_record(table,id)`, `get_document(doc_id)`, `calculator(expression)`, `submit(findings)`. Для Python используются JSON-словари с полем `action`; `findings` в submit — полный конверт `{episode_id, findings:[...]}`. `get_record` принимает row_id для CSV и doc_id для JSONL, не бизнес-ID. Таблицы: ledger, invoices, payments, fx, policy. Policy также доступна как документ `policy`.

Курсор — стабильное целое смещение в неизменяемой таблице эпизода. Размер страницы 1–50. Некорректные запросы и неизвестные ID расходуют шаг и возвращают одинаковую ограниченную ошибку. Максимум 100 шагов, включая submit; submit на последнем шаге принимается. Неотправленный ответ при исчерпании шагов или времени заменяется пустым, эпизод получает truncated=true. Тайм-аут проверяется при входе в очередной step; для произвольного зависшего внешнего агента организатору нужен процессный watchdog.

Калькулятор поддерживает +, -, *, /, скобки и десятичные числа. Использует Decimal, AST-whitelist, лимит длины и числа узлов; eval, вызовы функций, степени, доступ к файлам отсутствуют.

## Генератор и данные

Настройки: `invoices` 50–200, `errors` — независимые количества 0–3 для каждого типа, `interaction` = null / allocation_cutoff / fx_cutoff, `timezone` = +05:00 / +00:00 / -04:00 / +09:00. `payment_delay_days` (0–7, по умолчанию 5) задаёт максимальную задержку платежа. `transform` включает воспроизводимое переименование ID и перестановку таблиц. Неуказанный тип внутри явно заданного errors означает 0.

Типы: duplicate_invoice — вторичная пара проводок по одному счёту; payment_allocation — часть погашения ошибочно отнесена на unallocated; fx_conversion — неверная сумма конвертации банковского платежа; period_cutoff — признание выручки вынесено за период при дате оказания услуг внутри периода. Сочетания: частичное распределение и неверный период одного счёта; валютный платёж и неверный период связанного счёта. Это связанные нарушения в одной цепочке, не случайные ошибки в несвязанных строках.

Сначала создаются сбалансированная чистая книга и первичные документы. Затем применяются локальные причинные изменения, сохраняется до/после. Законные повторяющиеся суммы, разбитые платежи и возвраты не являются ошибками. Возвраты представлены отрицательными подписанными суммами и сторнирующими проводками; это явно выбранная конвенция синтетической книги. Валюты KZT, USD, EUR с разрядностью 2, JPY с разрядностью 0 и KWD с разрядностью 3. Конвертация учитывает разрядность обеих валют. При оплате выполняется переоценка задолженности; остаток после разбитых оплат закрывается точно. Деньги целые, курсы десятичными строками, округление ROUND_HALF_EVEN с нулевым допуском. Опубликованные времена содержат UTC-смещение; курс выбирается по локальной дате платежа, граница периода полуоткрытая. Записи не сравниваются между валютами без конвертации.

Экспорт: `artifacts/episodes/{train,dev}/{episode_id}/public/` содержит manifest.json, ledger.csv, invoices.jsonl, payments.jsonl, fx.csv, policy.json. Соседний `evaluator/` содержит truth.json и provenance.json. В поставке 10 открытых train- и 10 dev-эпизодов. Оба набора открыты, их нельзя называть скрытой проверкой жюри. Для закрытого прогона задавайте новые seed, сочетания настроек и transform; не помещайте evaluator-файлы в контейнер/рабочий каталог агента.

## Изоляция и честные ограничения

Evaluator/service работает в отдельном subprocess. Политика получает только initial observation и callable step; таблицы возвращаются копиями. Ни truth, ни provenance, ни seed не включаются в наблюдения, ошибки, info или промежуточную награду. В evaluation терминальная награда тоже 0; отчёт читает доверенный runner после завершения и не передаёт политике. Oracle живёт только в runner и используется для проверки потолка награды.

Это узкий JSON-контракт и разделение процессов для штатных адаптеров, **не security sandbox для враждебного Python-кода на одном OS-пользователе**. `AuditEnv` — доверенный runner, его report/reset не следует отдавать недоверенному агенту. При запуске произвольной программы организатор должен разделить пользователей/контейнеры и предоставить только канал step, без доступа к исходникам оценщика, открытым эталонам, системному shell, сети и evaluator-томам. Проект не заявляет, что один Docker-контейнер с открытыми train-эталонами сам по себе обеспечивает эту границу.

Данные намеренно просты: у каждого документа известна цепочка связей, ставки не моделируют реальный рынок, графы поставщиков неглубокие. Базовая сверка достигает F1=1 на опубликованном наборе. Это подтверждение корректности связей и оценщика, не доказательство сложности для LLM или пригодности для реального аудита. Произвольные часовые пояса IANA, DST, распознавание PDF и обучение модели не реализованы и не заявляются.

## Награда и проверка

`auditlab/scoring.py` публикует нормализацию, структурные ограничения и максимальное двудольное сопоставление: тип, точный канонический набор affected_ids, сумма, валюта и хотя бы один полный набор доказательств. Повторные выводы не сопоставляются повторно. Объяснение не влияет на награду. Некорректная отправка завершает эпизод с −1. Максимум 30 выводов, 10 evidence_ids, 1000 символов explanation.

`reward = clip(2*F1 - 1 - 0.002*inspection_steps, -1, 1)`; submit не считается inspection. P/R при нулевом знаменателе равны 0; для двух пустых наборов F1=1. Поэтому средние P/R на наборах с чистыми компаниями ниже среднего F1 — это следует заданной формуле.

Поле finding_results в итоговом отчёте доверенного оценщика содержит индекс и факт сопоставления каждого вывода. Оно не содержит expected-значений или скрытых issue_id и не попадает в step-наблюдения, info или награду evaluation-агента. Интерфейс показывает его только после завершения открытого train-эпизода.

Тестируются дубли, молчание, ложные обвинения, угадывание ID, отсутствие доказательств, валюта, деньги, неверный ввод, повторная отправка, тайм-аут, лимиты, calculator injection, смена ID/порядка, изоляция копий и скрытая награда. `independent_check` проверяет баланс до/после и восстанавливает расхождения по публичным данным кодом сверки, который не читает truth.

## Внешний агент и watchdog (v1.1)

Актуальные 10 train- и 10 dev-эпизодов перечислены в artifacts/episode-index.json. Ранее опубликованные примеры версии 1.0 сохранены по прежним путям для совместимости; в метрики версии 1.1 они не входят.

В генератор также добавлены корректные авансы с null-ссылками на счета. Наличие проводки unallocated или fx_revaluation само по себе не означает ошибку: эти счета используются и корректными операциями.

```sh
python -m auditlab.external --policy reconcile --seed 2026 --timeout 10
```

Доверенный runner запускает политику отдельным процессом в пустой временной рабочей папке с ограниченным набором переменных окружения. Агент получает начальное наблюдение через stdin и выдаёт JSON-действия по одной строке в stdout. Runner возвращает observation/reward/terminated/truncated; seed, config, reset, abort и report в этот канал не передаются. Последняя отправка завершает процесс агента; итог читает только runner. Наблюдения и итог сохраняются раздельно в artifacts/external-trajectory.jsonl и external-report.json.

Wall-clock watchdog охватывает ожидание ответа, блокировку чтения агентом и обмен через pipes. Зависший или упавший агент завершается, итог заменяется пустым, truncated=true. Предельный размер строки действия — 200000 символов. Это проверено отдельными тестами зависания и переполнения. Временная папка и сокращённое окружение не запрещают враждебному процессу читать другие доступные файлы OS-пользователя: для такого режима по-прежнему нужна внешняя контейнерная/пользовательская изоляция.

Полный список изменений — CHANGELOG.md. Новая версия меняет детерминированные эпизоды; для воспроизведения старого результата используйте соответствующий Git-коммит.
